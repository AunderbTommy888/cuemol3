## 前回指摘の対応確認

| 確認点 | 更新後の計画 | 判定 |
|---|---|---|
| Console を off にすると rc の取消手段がなくなる | runner の unmount cleanup で実行中の run に `cancelRun` を送り、残りの startup ファイルも中止する | 計画上で対処 |
| Root の unmount で gate が先に開く可能性 | release を Root の寿命ではなく、実行 Promise の完了に結び付ける | 計画上で対処 |
| worker の transaction 終了前に Undo/Redo 抑止が外れる | 残る制約として明記し、plugin 無効化の保留は実装コストに見合わないため採用しない | 制約を明示して受容 |

取消には既存の [runControl.ts](../../tritium/react-gui/src/plugins/console/worker/runtime/runControl.ts) の `cancelRun` を使えます。これは停止フラグを立て、追跡中のダウンロードも取り消す処理です。取消要求の送信だけで gate を開けず、実行完了まで待つ方針は、この API の挙動と整合しています。

Undo/Redo 抑止の空白が完全に解消したとは判定していません。ただし、今回の計画はその制約を明示して採用範囲を決めているため、同じ問題への追加対応を再度求めません。取消完了までの時間は実測していません。

## その他の確認

前回の修正箇所以外も、CLI の起動・待機中の取消、text / qax の cwd と継続実行、plugin の設定読込・再 mount、style の予約 ID・読込失敗時の後始末・GUI 設定の保存との関係を見直しました。これまでの指摘への対処は維持されています。

計画中の「user set が存在しない場合の優先順位」は、実装開始時に確認して対処する項目として既に記載されているため、重複して指摘していません。
